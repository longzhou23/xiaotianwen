## 已通过项目

1. 发现 Ubuntu 官方源使用 `docker-compose-v2`，修正部署脚本；
2. 在目标机安装 Docker 29.1.3 和 Compose 2.40.3；
3. 恢复 public/private 目录和实例数据；
4. 按 private `plugins.lock.yaml` 恢复 15 个启用插件；
5. 确认已停用的 NapCat 插件未被恢复；
6. 生成 268 MB 实例备份；
7. 恢复到独立 `restore-check` 目录；
8. 备份与恢复后的 `plugins.lock.yaml` SHA-256 一致；
9. 未创建 secret 文件，未启动任何服务。

## 演练中发现并修正的问题

- `docker-compose-plugin` 不是 Ubuntu 24.04 默认源中的包名；
- 干净机器在安装依赖前没有 Git，bootstrap 必须先安装系统依赖；
- AntiPromptInjector 的锁文件路径与实际公共目录名不一致；
- Windows `scp` 同步会丢失 Unix 执行位并引入 CRLF；真实 Git clone 不应使用这种同步方式。

## 结论

当前已经验证了“代码/插件/实例数据/备份恢复”的第一段链路，但还不能宣称完整可复现部署。要完成全链路，需要先固定 AstrBot 主程序来源和版本，并解决目标机到 GitHub 的网络路径，然后重新做一次真实 Git clone、主程序安装、secret 注入和服务启动演练。
