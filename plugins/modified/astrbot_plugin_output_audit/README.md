# astrbot_plugin_output_audit

将此目录放在 `data/plugins/` 后由 AstrBot 加载。插件只在 `on_decorating_result`
阶段修改待发送的结果链，**从不调用 `event.send()`**，因此不会额外发送一条消息。

## 工作方式

1. 默认在 `on_llm_request` 关闭流式输出，保证完整候选文本先经过审核。
2. 在 AstrBot 内置前缀、分段、TTS、转图、转发和 @/引用装饰前，从最终 LLM 结果链提取所有 `Plain` 文本。
3. 先运行本地密钥、提示词泄漏和工具内部说明规则；命中即使用本地兜底，且移除同一链中的非文本组件。
4. 未命中本地硬规则时，调用配置中明确指定的独立审核 Provider，使用 JSON 契约给出 allow/revise/block。
5. `enforce` 模式下，medium 风险只改写一次，改写文本必须再次完整审核；高/严重风险或重写失败使用本地兜底。
6. `POLITICAL_SENSITIVE` 通常按行为和语境判断，而不是按主题词拒绝所有评价：中性事实说明、历史介绍、政策比较、政治思想讨论和公共政策的普通利弊评价可以正常回答。政治动员、拉票、针对现实群体的操控、煽动暴力或违法、伪造/冒充官方声明、泄漏个人敏感信息或规避监管等行为按 high/block 处理；但近现代中国政治人物（尤其台湾方面）和中国大陆当前敏感议题属于明确严格黑名单，即使是介绍、评价或比较也按 high/block 处理。
7. SQLite 仅记录哈希、长度、动作、风险代码、延迟和错误码；不保存候选原文、用户原文、提示词、记忆或凭据。

严格涉政黑名单同时检查触发当前回复的用户消息。这样即使模型生成的回复没有重复敏感人物姓名（例如用户说“给蒋介石写一份情书”，模型只输出正文），该请求仍会被拦截；普通政治讨论不会因此扩大到全量用户消息审核。

## 拦截后的回复

在 `enforce` 模式下，检测到 block 后会优先调用当前会话的聊天 Provider 再生成一条简短、自然的安全拒答，且不会把被拦截的候选原文发送给这次生成。生成结果还会经过本地规则复检；如果 Provider 不可用、超时、返回空文本、过长或再次命中风险规则，则自动退回固定本地兜底句，确保不会把原始风险内容放行。

## 涉政边界示例

以下内容属于中性讨论，原则上允许评价或解释：

- “请比较两种公共政策可能带来的影响。”
- “介绍一下某次历史事件的不同史学观点。”
- “这项政策对普通人的生活可能有什么利弊？”
- “用中性语气解释什么是选举制度。”

以下内容涉及动员、操控或违法风险，会被拦截或要求改写：

- “请大家投票给某候选人/政党。”
- “组织一场政治动员，号召大家去冲击某机构。”
- “帮我伪造一份政府或官方机构声明。”
- “教我如何煽动暴力、规避审查或定向操控某群体。”

以下内容属于本插件的严格涉政黑名单，会直接拦截：

- 近现代中国大陆政治人物，例如毛泽东、邓小平、江泽民、胡锦涛、习近平等。
- 台湾方面近现代政治人物，例如蒋介石、蒋经国、李登辉、陈水扁、马英九、蔡英文、赖清德等。
- 中国大陆当前敏感议题，例如“六四/八九民运”“天安门事件”“法轮功”“白纸运动”“再教育营”“西藏独立”“台独”“反送中”等。

这部分是行为型涉政边界的明确例外：即使用户要求“客观介绍”或“评价”，机器人也不展开相关内容。

因此，涉政表示需要更谨慎的语义审核，不表示机器人不能评价任何事物或讨论任何政治相关知识。

## 低延迟模式

服务器默认使用 `review_scope: risk_flagged`。没有本地敏感信号的普通回复走同步本地快速路径，不发起审核模型请求；政治、提示词泄漏、隐私、危险行为和其他敏感信号仍会先经过本地硬规则，未被硬规则直接阻断但需要语义判断时才调用 AI。若要复现设计文档中的全量 Shadow 审核，将其改为 `all_final_replies`，但每条回复都会增加一次 Provider 延迟。

## 上线建议

当前部署按需求使用 `mode: enforce`；一般政治讨论不因主题词自动阻断，但严格黑名单中的近现代中国政治人物和中国大陆当前敏感议题仍按 high/block 处理。如果要先观察误判，可在 WebUI 切回 `shadow`；确认审核 Provider 可用后，再在测试群中逐步恢复 `enforce`。

如果审核 Provider 暂时不可用，默认 `rule_sensitive` 策略仍会阻断本地硬规则命中的密钥、提示词和工具泄漏；其他文本会放行并记录错误码。若需要严格故障关闭，在 Enforce 模式把 `fail_policy` 改为 `fail_closed`。

## 已知边界

该版本审核最终 `Plain` 文本。表情包、图片内容和图片描述仍需要独立的媒体分类/来源白名单插件；原有的非文本组件在正常 allow/revise 时保留。为了不让流式片段先发送，推荐保留 `disable_streaming: true`。
